Baseline: PR #173 preview `3b571f2` (= merged main + this branch). Method: 24
screenshots (desktop/mobile × light/dark), 6 section critiques by fresh-context
vision agents against DESIGN.md rules, plus a token/implementation audit.
Source screenshots: `/tmp/design-review/`. Findings below are filtered against

## A. System-level findings (cross-section)

### A1. Shadow policy conflict — needs owner decision
DESIGN.md (updated): *Tonal Layer Rule — no drop shadows in either theme.*
Implementation: ~25 `box-shadow` uses in `app.scss` + 5 in `maplibre-gl.scss`
(the "one soft shadow" convention agreed during #150).

Independent critique consensus: over **pale winter map imagery in light mode**,
tone alone does not separate floating panels (#fdfefd on near-white tiles) —
the shadow is load-bearing there. On **panel-on-panel** surfaces (drawer vs
page, toolbar vs drawer) tonal separation reads cleaner and the shadow adds
noise.

**Options:**
1. Strict spec: strip all shadows, rely on tone + ridges (+ deeper panel
   tones where needed).
2. Hybrid (recommended): tonal-first everywhere; keep the one soft shadow
   *only* for chrome floating directly over map imagery (fabs, floating
   search card, bottom sheet) — codify the exception in DESIGN.md.

### A2. Radius ramp — spec is internally inconsistent; implementation is chaos
- DESIGN.md frontmatter: 4px controls / 8px cards+panels / 16px dialogs.
- DESIGN.md Components section: buttons 6px, cards 6px, dialogs 20px.
- Implementation census: 2, 4, 5, 6, 8, 10, 12, 16, 25, 40, 100, 999px.

**Ask:** pick one ramp (recommend the frontmatter 4/8/16 — it is the cleaner
instrument geometry). Then normalize components + add a radius lint to the
visual matrix script.

### A3. Night map chrome — spec vs earlier owner rule
DESIGN.md's night palette (pine panels + ice glyphs) vs the #150 rule
"map keeps light basemap + light chrome in both themes". The map critique
flagged the light chrome as the biggest night-mode gap. **This is your call** —
keep the owner rule (light chrome = deliberate) or theme the floating map
chrome per DESIGN.md while keeping the light basemap. (Middle ground: chrome
follows theme, basemap stays light — controls sit on white chips in Day,
pine chips in Night.)

### A4. Control labels — sentence case vs Instrument Label Rule
"Select date", search placeholder, and several chip labels are sentence case;
spec wants Barlow Semi Condensed UPPERCASE +0.167em on controls. Note: the
dashed toolbar-input frame and current input styling were explicitly matched
to staging during #150 — that stays unless you reopen it. Uppercasing the
*labels* is independent of the input chrome and low-risk.

## B. Section findings

### B1. Header toolbar
1. **[high] Hover feedback nearly invisible** — no tonal lift on toolbar
   buttons (both themes). Suggest hover wash rgba(black .06)/rgba(white .1)
   per DESIGN.md Buttons, 150ms ease.
2. **[high] Header identical in Day and Night** — same deep-green slab; on
   Night it is the *least* contrasted element. If deliberate (brand anchor),
   keep but consider a night hairline ridge below. Related to A3.
3. **[med] Date stepper fragmentation** — `‹ [Select date] 📅 ›` reads as
   3+ loose pieces. Suggest one 4px segmented group with internal ridge
   dividers.
4. **[med] Right icon cluster** — gift/chat/translate/theme at equal weight,
   no grouping. Suggest 24px gap between action groups; theme toggle gets a
   persistent current-mode glyph state.
5. **[med] Mobile "Select dat…" truncation** — shorten label/icon-only below
   600px.
6. **[low] Mixed icon chrome** — hamburger in a chip, right icons bare;
   logo glyph optically heavier than 24px action icons.

### B2. Side menu (currently placeholder — content pending)
1. **[high] No panel structure** — flat page-tone void + construction glyph.
   When content lands: panel-on-page tone + ridge right edge; even the
   placeholder could carry the ridge to prove the system.
2. **[med] LOG IN floats** — needs the control treatment (uppercase
   condensed, 4px outline button) docked in a footer group.
3. **[med] Version footer** — loose underlined links; suggest BUILD
   micro-label (uppercase condensed 10–11px), mono hashes, muted tone,
   underline on hover only. Commit hash currently spends gold — reserve
   gold (A5 head-torch).
4. **[med] Desktop drawer width while empty** — full ~415px column for a
   placeholder cramps the map (spec: map dominant). Suggest overlay-mode
   or collapsed until content exists.
5. **[low] Close affordance** — small circled arrow; give it position/size
   parity with the open control.

### B3. Hut detail — header ("Briefing Header")
1. **[high] Gold wash on the forecast "Today" card** — solid gold-tinted
   block in both themes. Violates head-torch rule. Suggest: panel-tone tile
   + 1px gold ridge (or 4px gold left bar), gold stays in icon/temp only.
2. **[high] Title voice inconsistent** — desktop regular vs mobile bold;
   neither reads as the spec headline (Barlow Semi Condensed ~28–32px
   semibold). Unify across panel/sheet.
3. **[med] Section headers gold in both themes** — "Weather"/"Location" as
   bright gold text at night = decoration. Suggest ink/ice headers + short
   gold tick rule; one gold element per viewport.
4. **[med] Night secondary temps** — min temps/precip grays nearly vanish
   on #112119. Suggest ice-tinted secondary (~#7fa89e).
5. **[med] Empty hero eats mobile first paint** (~25%) — collapse to
   one-line "No photos yet · Add" row on mobile.
6. **[low] Elevation glyph** reads as warning-triangle to fresh eyes.
   (Current ▲ marker was deliberate — verify we still like it; alternative:
   mountain glyph.)
7. **[keep]** Briefing line composition, STANDARD-hut chip pattern (label
   uppercase + value sentence + tonal bar), map halo on hut label, panel
   ~30% width keeping map dominant.

### B4. Hut detail — body & footer
1. **[high] Availability is one interaction deep** — the calendar opens
   only via the date chip; the panel body leads with weather. Suggest a
   compact month strip / first-free-nights summary row directly in the body
   (this is the product's core signal — availability should outrank
   weather).
2. **[med] Forecast tiles borderless + uneven** — only "Today" is a card.
   Uniform 8px tiles + ridge; "today" via tonal fill, not gold (ties to B3.1).
3. **[med] Drawer separation** — shadow does all the work in light mode;
   ridge + tonal step would carry it (A1/A3 dependent).
4. **[med] Footer version links** — same BUILD treatment as B2.3.
5. **[low] Left drawer footer slab in dark** — mid-gray field outside the
   night tonal stack; rest it on pine-panel + ridge.
6. **[keep]** Day/night panel pairing (#fdfefd/#f6f9f7 vs #112119/#0a140f),
   description typography + more-link, attribution micro-copy, location
   row pattern.

### B5. Map controls
1. **[high] Rail circles: translucent wash + shadow** — muddies over
   terrain. Suggest opaque panel fill + 1px ridge, shadow off (floating
   fabs keep theirs — A1 hybrid).
2. **[med] Mobile activity rail dominates** — 12 × ~64px circles run the
   whole left edge (~20% width). Suggest collapse-to-chip + expand grid,
   or 40px circles.
3. **[med] Attribution block** — square-corner bare text wrapping 3 lines,
   collides with scale bar, no halo. Single-line chip + halo, scale bar
   offset 8px. (Note: "matt" text flagged by the critic is a *map label*
   — the village Matt, not app text.)
4. **[med] Filter-count badge** on the rail button — low salience; filled
   info-tint chip, 4px.
5. **[low] Preview ribbon** clips the mobile logo corner — small corner
   badge on narrow viewports.
6. **[keep]** Gold inset ring on active chips (exactly the beam), desktop
   map dominance, fab pairing, toolbar hue-family shift day→night.

### B6. Search
1. **[high] Light input ghost** — white field on #fdfefd panel, hairline
   only. Recess it: ridge border + page-tone fill.
2. **[med] Empty-state panel too tall** (~620px void) — cap to content
   (~40vh); dark panel already demonstrates tonal separation done right.
3. **[med] Mobile search entry salience** — bare magnifier among header
   icons; filled chip or ≥44px target.
4. **[med] Results/selected states not yet captured** — round 2.
5. **[keep]** Same-instrument day/night layout identity; sentence-case
   empty-state copy.

### B7. Dialog boxes — round 2 (not yet captured)
Date picker (WdSelectDate), external-booking dialog, mobile search sheet.
Auth-gated dialogs (photo upload, favorites) skipped.
