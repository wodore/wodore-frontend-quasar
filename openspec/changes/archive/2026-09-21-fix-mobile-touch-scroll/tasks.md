## 1. Fix mobile touch scroll in bottom sheet

- [x] 1.1 Reset `touch-action` to `auto` on `.sheet-content` (via `::part(content)`) when sheet is not expanded — `expand-to-scroll` sets `overflow-y: hidden` on `.sheet-content` when not expanded, and the library's WebKit workaround declares `touch-action: pan-y` there, handing vertical gestures to an element that cannot scroll (gesture consumed, host never expands). Note: the override must be `auto`, NOT `pan-x` — touch-action restrictions apply along the whole ancestor chain of the touch target, so `pan-x` blocks vertical panning of the host scroller in Blink/Gecko (verified by A/B test in Chromium touch emulation; with `pan-x` vertical drags on content did nothing, with `auto` they expand the sheet). Scoped to `@media (pointer: coarse)` and `:not([data-sheet-state="expanded"])` so it only applies on touch devices when the sheet isn't fully expanded.
- [x] 1.2 Add `:touch-move-stop-propagation="false"`, `:touch-start-prevent-default="false"`, `:touch-angle="10"`, `:threshold="0"` to Swiper in `WdAccommodationAvailabilities.vue` — prevents Swiper from claiming near-vertical touch gestures so they can reach the host scroll.
- [x] 1.3 Add `:touch-move-stop-propagation="false"` and `:touch-start-prevent-default="false"` to Swiper in `WdWeatherForecast.vue` — same touch coexistence fix.

## 1b. Update pure-web-bottom-sheet and re-open sheet on new content
